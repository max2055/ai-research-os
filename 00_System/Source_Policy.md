# 来源政策 v0.2

## 1. 目的

来源等级用于评估一条信息作为事实证据的可靠性，不用于判断观点是否正确。

高等级来源也可能存在偏见、口径限制或选择性披露。

## 2. 来源等级

### A 级：原始与权威来源

包括：

- 监管申报和正式公司公告。
- 经审计财务报告。
- 财报电话会正式记录。
- 官方产品文档、定价和 API 文档。
- 同行评审论文或作者正式技术报告。
- 法律法规、监管机构文件。
- 可复核的原始数据集。

使用要求：

- 保留原始链接或本地文件。
- 记录发布日期、版本、报告期和适用范围。
- 公司材料中的预测和宣传仍需标记为公司陈述。

### B 级：高质量直接或专业来源

包括：

- 管理层和核心技术人员的正式访谈。
- 有方法说明的专业研究报告。
- 权威专业媒体的原创报道。
- 可验证的客户案例。
- 高质量行业会议材料。

使用要求：

- 识别信息提供者的利益关系。
- 尽可能与 A 级来源交叉验证。
- 客户案例不能直接外推总体采用率。

### C 级：一般二手来源

包括：

- 普通新闻媒体。
- 分析师文章和行业评论。
- 有作者身份的博客。
- 播客和非正式访谈。

使用要求：

- 主要用于发现线索、观点和研究问题。
- 关键事实应寻找 A 或 B 级来源验证。
- 不把转载数量当作独立证据数量。

### D 级：未经验证的线索来源

包括：

- 匿名社交媒体消息。
- 未提供出处的截图和转述。
- 论坛和社区传言。
- 来源不明的 AI 生成内容。

使用要求：

- 只能进入 Inbox 或研究队列。
- 不得单独支持 Thesis 或最终报告中的关键事实。
- 在获得独立验证前标记为 `unverified`。

## 3. 来源独立性

多项来源只有在信息生成过程相互独立时，才能视为多项证据。

下列情况通常不是独立来源：

- 多家媒体引用同一份公司新闻稿。
- 多篇文章引用同一个匿名消息源。
- 研究报告重复引用同一组底层数据。
- AI 摘要重复转述同一篇文章。

Source 记录应在已知时注明共同上游来源。

## 4. 来源选择顺序

针对首个研究专题，按以下顺序查找：

1. 财报、监管文件和投资者材料。
2. 官方产品、定价、API 和安全文档。
3. 财报电话会和正式管理层发言。
4. 可核验客户案例。
5. 专业研究和原创报道。
6. 普通媒体与社区线索。

## 5. 时效与版本

- 动态网页记录访问日期。
- 产品文档记录适用版本。
- 财务数据记录财年、季度和币种。
- 价格记录计价单位和生效时间。
- 被修改或撤回的来源不得静默覆盖，应保留版本说明。
- 显式采集的原始 bytes 保存到 `01_Inbox/_assets/<SOURCE_ID>/`，每个版本
  记录 SHA-256、采集时间、media type、原始位置和最终位置。
- 同 canonical URL 或同内容 hash 必须先提示重复；跨项目复用永久 Source ID。
- HTML/PDF 提取文本是可重建派生物，不能替代原始资产。
- 自动提取的发布日期只写入 `published_date_proposal`；研究者确认后才可改变
  `published_at`。
- RSS、GitHub Release、arXiv 和 SEC 自动化只允许显式 allowlist/query，
  单次返回数量有硬上限，且发现候选不会自动创建 Source。
- 采集前必须遵守 robots、许可、访问频率与服务条款；自动化不得绕过登录、
  付费墙或其他访问控制。

## 6. 最小 Source 记录

正式 Evidence 所引用的 Source 至少包含：

```yaml
id:
title:
publisher:
published_at:
accessed_at:
url:
local_path:
source_grade:
source_type:
canonical_url:
asset_paths: []
content_sha256:
fetched_at:
processing_status:
processing_error:
```

URL 和 `local_path` 至少一个有效。

原始资产可能受许可或隐私限制，默认不提交 Git；必须按恢复手册单独加密备份。

## 7. 使用限制

- A 级公司公告可证明“公司披露了什么”，未必证明披露内容已被独立验证。
- B 级客户案例可证明案例存在，不能证明普遍性。
- C 级分析可提供推理和反方观点，不能替代原始经营数据。
- D 级材料只能作为研究线索。
- 来源等级不能替代对数据口径、利益冲突和作用机制的分析。

## 8. 报告披露

当核心结论主要依赖以下情况时，报告必须明确披露：

- 单一来源。
- 公司自述。
- 未公开方法的数据。
- 小样本客户案例。
- C 或 D 级来源。
- 无法获得原始材料。
- 来源之间存在未解决冲突。
- reviewed Event 所依赖的 Source 记录尚未完成 Source 级人工审核。

## 9. 审核范围

Source、Event 和处理进度采用独立状态：

- Processing 只回答流程动作是否完成。
- Source review 核验完整来源记录及其 provenance、等级、摘要和局限。
- Event review 核验该 Event 中实际使用的具体主张、Source anchor 和推理边界。

处理完成、生成 Event 或批准 Event 均不得自动批准 Source。reviewed Event 引用 pending Source 时保留 `REV003`，用于追踪 Source 级治理债务。
