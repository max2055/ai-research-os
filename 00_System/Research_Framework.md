# AI 产业研究框架 v0.1

## 1. 框架目的

本框架用于把零散信息转化为可验证的产业判断和投资含义。

研究不以“覆盖了多少新闻”为完成标准，而以是否能够回答以下问题为标准：

1. 产业正在发生什么变化？
2. 变化由哪些关键变量驱动？
3. 价值和控制权正在向哪里迁移？
4. 哪些公司能够获取价值，哪些公司可能失去价值？
5. 当前市场预期与研究判断有什么差异？
6. 什么证据能够支持、削弱或推翻当前判断？

## 2. 证据到结论的推理链

所有重要结论必须沿以下结构表达：

```text
Source
→ Fact
→ Event
→ Mechanism
→ Thesis
→ Company impact
→ Investment implication
→ Observable indicator
```

各层含义：

- `Source`：事实的原始出处。
- `Fact`：来源直接支持的可验证陈述。
- `Event`：对产业状态产生影响的变化。
- `Mechanism`：事件如何影响供需、成本、价值链或竞争。
- `Thesis`：可以持续验证和证伪的研究判断。
- `Company impact`：对具体公司的收入、成本、护城河或风险影响。
- `Investment implication`：对预期差、催化剂、风险和估值的含义。
- `Observable indicator`：未来用于验证推理链的指标。

不得跳过中间机制，直接从产品发布推导投资机会。

## 3. 三级研究结构

### 3.1 产业层

#### 产业定义

- 产业解决什么问题？
- 客户是谁？
- 谁为产品或服务付费？
- 产业边界和相邻产业是什么？

#### 产业空间

- 当前市场规模和可服务市场。
- 增长来自新增需求、替代需求还是价格变化。
- 增长是否受到算力、数据、人才、监管或客户预算约束。

#### 价值链

- 上游投入是什么？
- 中游平台和控制层是什么？
- 下游应用和付费者是谁？
- 利润池当前分布在哪里？
- 哪些环节具有议价权？

#### 关键变量

- 技术性能与成本。
- 供给能力。
- 客户采用和预算。
- 商业模式。
- 监管、安全和责任。
- 生态标准和互操作性。

#### 产业阶段

- 技术验证期。
- 产品验证期。
- 商业模式验证期。
- 规模化扩张期。
- 成熟与整合期。

研究必须说明所处阶段，不能用成熟产业的估值逻辑解释尚未完成商业验证的赛道。

### 3.2 赛道层

每个赛道统一回答：

1. 赛道定义与边界。
2. 客户问题和付费意愿。
3. 市场规模及增长驱动。
4. 技术路线及性能约束。
5. 竞争格局和主要参与者。
6. 商业模式与单位经济性。
7. 数据、分发、生态、资本和监管壁垒。
8. 未来三年的关键变量。
9. 受益和受损环节。
10. 可验证指标与风险。

### 3.3 公司层

#### 公司定位

- 公司处于价值链什么位置？
- 它控制什么稀缺资源？
- 它依赖哪些供应商、平台或渠道？

#### 产品

- 产品解决什么问题？
- 谁使用，谁决策，谁付费？
- 使用频率、替代对象和迁移成本是什么？
- 产品能力是演示、试点还是生产部署？

#### 商业模式

- 收入按席位、订阅、用量、任务还是结果计费？
- 收入是新增预算还是替代现有预算？
- 毛利率和边际成本如何变化？
- 推理成本、实施成本和客户成功成本是否可持续？

#### 竞争优势

- 技术。
- 数据。
- 权限和工作流。
- 分发。
- 品牌和客户信任。
- 开发者及合作伙伴生态。
- 规模经济和资本能力。

每项优势必须说明其持续条件和失效条件。

#### 经营质量

- 收入增长。
- 毛利率。
- 经营利润和自由现金流。
- 客户集中度。
- 净收入留存。
- 剩余履约义务或订单。
- 销售效率。

#### 管理层

- 资本配置。
- 技术与产品判断。
- 承诺兑现记录。
- 激励机制。
- 对风险和不确定性的表述质量。

#### 估值与预期

- 当前价格隐含了什么增长和利润假设？
- 市场共识是什么？
- 研究判断与共识的差异是什么？
- 哪些事件可能促使预期修正？

估值是研究结果的约束条件，而不是用一个估值倍数替代产业研究。

## 4. AI Agent 企业软件专题框架

### 4.1 产品层

- Agent 是独立产品、现有功能还是跨应用入口？
- Agent 能否规划、调用工具、执行并验证结果？
- 人是否必须持续参与？
- 能否处理真实权限、异常和责任边界？

### 4.2 客户采用层

- 使用来自试验预算还是正式业务预算？
- 部署周期多长？
- 谁是购买决策者？
- 是否进入核心工作流？
- 使用频次和续费情况如何？

### 4.3 价值迁移层

- 用户入口由谁控制？
- 企业上下文由谁掌握？
- 数据和权限由谁治理？
- 跨系统工作流由谁编排？
- 结果由谁负责？
- 最终定价权由谁拥有？

### 4.4 公司影响层

对每家公司分别判断：

- 增量收入。
- 原有收入被替代的风险。
- 毛利率变化。
- 分发优势。
- 数据和权限优势。
- 产品架构约束。
- 商业模式冲突。
- 合作伙伴依赖。

## 5. 投资含义框架

只有在产业和公司机制清晰后，才评估投资含义。

### 5.1 预期差

- 市场当前相信什么？
- 哪项关键变量可能被高估或低估？
- 研究证据是否足以形成不同判断？

### 5.2 催化剂

- 财报或经营指标。
- 产品正式商业化。
- 定价变化。
- 大型客户采用。
- 竞争格局变化。
- 监管或行业标准变化。

### 5.3 风险

- Thesis 错误。
- 方向正确但时间过早。
- 公司受益但估值已充分反映。
- 技术成功但商业模式失败。
- 收入增长但单位经济性恶化。

### 5.4 输出等级

- `Watch`：值得跟踪，但证据不足。
- `Research`：存在明确研究问题，需要补充证据。
- `Thesis`：形成可证伪判断。
- `Investment candidate`：产业、公司、预期差和估值均具备进一步研究价值。

Research OS 不自动产生买入或卖出指令。

## 6. 研究完成检查

一项研究在进入报告前必须回答：

- [ ] 研究问题是否明确？
- [ ] 研究边界是否明确？
- [ ] 是否使用了优先级足够高的来源？
- [ ] 是否区分事实、推断和判断？
- [ ] 是否解释了作用机制？
- [ ] 是否包含反面证据和替代解释？
- [ ] 是否提出可证伪条件？
- [ ] 是否定义后续观察指标？
- [ ] 是否区分产业价值与股东回报？
- [ ] 是否说明未知事项和置信度？
