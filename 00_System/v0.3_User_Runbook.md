# AI Research OS v0.3 Website Runbook

Status: Web-only product baseline
Updated: 2026-08-18
Scope: RCP-v03-011 website operation

AI Research OS 的唯一用户产品界面是本地网站。Markdown 继续是研究对象的权威事实源；
Candidate SQLite、`operations.db`、索引、网站视图和指标是 operational 或派生状态。
网站启动时启动一个受监督 Worker，网站停止时 Worker 同步停止，停机期间不执行定时任务。

## 启动

从 canonical 主工作目录使用唯一入口：

```bash
python -m research_os.ui
```

打开 `http://127.0.0.1:8765/home`。产品只绑定 loopback，不支持公网或多用户部署。

启动前会执行只读 preflight。以下任一情况都会在建库、迁移或启动 Worker 前直接失败：

- 代码根目录与运行数据根目录不同；
- 从 linked Git worktree 启动；
- Git 根目录或合并状态无法确认；
- Candidate DB schema 或 integrity 异常；
- 已存在的 Operations DB schema 或 integrity 异常。

在 `/health` 的 `Runtime Identity` 区域核对 root、branch、commit、dirty、interpreter、
package path、Candidate DB 和 Operations DB。发现路径不是预期 canonical 目录时立即停止网站，
不得继续写入或运行任务。

## 导航与日常工作

网站导航分为两个工作区域：

- 研究：产业首页、项目、公司、证据、影响、分析、决策与评审；
- 运行：Pipeline、Operations、Health、模型设置与发布检查。

常用入口：

| 工作 | 网站入口 |
|---|---|
| Candidate 查看、筛选、dismiss、restore、promote | `/pipeline/queue` |
| Source 创建、抓取、处理与日期确认 | `/sources` |
| Event、Report 与研究草稿 | `/evidence`、`/reports` |
| 具名人工 Review | `/reviews` |
| Impact、Analysis、Forecast、Valuation、Recommendation | `/impact`、`/analysis`、`/decision` |
| Project、Entity、Action 与关系维护 | `/projects`、`/companies`、`/operations/actions` |
| Channel 与 discovery | `/pipeline/channels`、`/operations/discovery` |
| 定时计划 | `/operations/schedules` |
| 手动 Job 与运行历史 | `/operations/jobs` |
| 本地与 durable backup | `/operations/backups` |
| 校验、索引、Worker、数据库、备份和发布状态 | `/health` |
| LLM provider 与模型 | `/llm` |

所有权威写入都必须经过服务器端 validation、预览、显式确认、具名 actor、目标版本检查、
原子提交与审计。页面缺少这些步骤时不要继续操作。

## 定时任务

计划只在 `/operations/schedules` 创建、编辑、暂停、恢复或立即运行。
`09_Automation/operational/operations.db` 是 cadence、enabled、retry、timeout、lease、
heartbeat、运行历史和审计的唯一运行权威。

Channel Markdown 中的旧 `schedule`、`timezone`、`enabled` 等字段只在首次切换时导入，
之后不再驱动 Worker。已有 `JOB-*.md` 仅保留为历史记录；新运行不创建 Job Markdown。

Worker 只能执行明确 allowlist 中的 operational Job。它不能批准 Source、Event、Impact、
Analysis、Forecast、Resolution、Valuation、Recommendation 或 Review，也不能修改 Thesis
结论或 confidence。

## 人工研究边界

- Candidate promote 只创建 pending Source，并保留原始资产和 provenance；不自动批准。
- Source processing 与 Event extraction 不等于 Source 或 Event review。
- Analysis 输出不是事实来源；只能形成 pending 草稿或 proposal。
- Forecast 只能在真实 resolution date 与可观察 outcome 出现后由具名人工处理。
- Recommendation 是研究草稿，不是交易或组合执行指令。
- 冲突证据必须同时保留，不得通过数量投票或模型输出自动裁决。

## Weekly 与 Monthly

Weekly 从 `/operations`、`/reviews`、`/health` 检查七天内的失败运行、Candidate 决定、
新增 Source/Event、Impact 修改、Forecast due、Action aging、Channel freshness、索引漂移和
备份状态；用网站创建真实日期、具名 reviewer 的 Review 和后续 Action。

Monthly 从 `/operations/metrics`、`/health` 和 `/health/release` 检查 Sector/Company/Channel
覆盖、来源独立性、冲突、模型质量、Forecast calibration、性能、成本、许可、备份年龄与
恢复准备度。不得回填尚未自然发生的 Pilot、cadence 或 Forecast outcome。

## 备份与恢复

在 `/operations/backups` 预览并确认 Candidate snapshot 或 durable backup。Durable backup
同时覆盖 Candidate DB、Operations DB 和 Source assets；浏览器不接收 config path、recipient、
token 或 private identity。

`/health` 对缺失、失败、无效或超过 24 小时的 durable receipt 分别显示
`BKP_DURABLE_MISSING`、`BKP_DURABLE_FAILED`、`BKP_DURABLE_INVALID`、
`BKP_DURABLE_STALE` P1 告警，并以 24-hour RPO 为日常检查边界。完整密钥托管、remote
verify、disposable restore 与灾备验收只在 `00_System/Recovery_Runbook.md` 维护，不属于
日常产品操作。

## 停止与故障处理

停止网站后确认 `/health` 不再可访问，Worker 子进程退出，`operations.db` 的运行计数不再增长。
不要加载旧 OS scheduler，也不要从其他 worktree 启动第二个网站。

| Priority | Trigger | Immediate action |
|---|---|---|
| P0 | secret exposure、权威数据丢失、绕过 actor/preview/audit 的写入 | 停止网站，保留日志，停止任何清理写入，进入安全/恢复审查 |
| P1 | 数据库 integrity、Source hash、durable backup 或 Worker restart budget 失败 | 停止写入与 discovery，保留现场，只在 disposable copy 恢复 |
| P2 | 单个 Channel/Job 失败、stale lease、index drift、逾期 Review | 暂停受影响计划，查明根因后幂等重试 |
| P3 | 可用性或性能问题 | 记录可复现路径和 Runtime Identity，继续未受影响工作 |

安全重试要求先核对既有 run/action 状态。不得删除 lease、backup、Candidate action、
Source asset、历史 Job 或 migration evidence 来让重试“通过”。
