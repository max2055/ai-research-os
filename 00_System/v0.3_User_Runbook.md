# AI Research OS v0.3 User Runbook

Status: engineering baseline
Updated: 2026-08-10
Scope: F-019 local single-user operation

This runbook operates the current repository. Markdown is authoritative for research
objects; the Candidate SQLite database, indexes, Dashboard views, and metrics are
operational or derived state. Commands default to read-only or dry-run unless they
show an explicit `--apply`.

## Install and configure

Run from the repository root. The supported environment for this branch is:

```bash
PYTHONPATH=src /Users/max/.venvs/ai-research-os/bin/python -m pip install -e ".[dev,ui]"
PYTHONPATH=src /Users/max/.venvs/ai-research-os/bin/python -m research_os --root . doctor
PYTHONPATH=src /Users/max/.venvs/ai-research-os/bin/python -m research_os --root . validate
```

Success means doctor has no unresolved runtime/asset failure and validation reports
`0 errors, 0 warnings`. Installation changes only the external virtual environment;
doctor and validate are read-only. Keep provider keys in ignored local configuration
or the loopback-only LLM settings store. Never place secrets in Markdown, Job messages,
shell history, screenshots, or Git.

## Failure response

| Priority | Trigger | Immediate action | Escalation |
|---|---|---|---|
| P0 | suspected secret exposure, authoritative data loss, or unauthorized Web mutation | stop jobs/UI, preserve logs, rotate affected secret, make no cleanup write | owner immediately; security/recovery review before restart |
| P1 | validation errors, Candidate DB integrity failure, hash mismatch, backup failure over RPO, or repeated Source corruption | stop applies and discovery, preserve files, restore to a disposable copy first | owner same session; open Action and recovery evidence |
| P2 | one Channel/job failure, stale lock, index drift, overdue review, or stale data | disable affected Channel if needed, retry safely after root cause, rebuild derived index | weekly review if not resolved that day |
| P3 | usability issue, slow query inside SLO, or documentation mismatch | record reproducible details and continue unaffected read-only work | backlog/monthly review |

Safe retry means the operation is idempotent or its prior Job/action state has been
checked. Never delete a lock, backup, Candidate action, Source asset, or migration
manifest merely to make a retry succeed.

## Secrets and Escalation

Keep secrets outside Git and outside research objects. Health and Operations must
show presence/status only, never values. Escalate any suspected disclosure as P0.
Escalate any request to expose the UI beyond loopback, add a Web mutation route,
change research rules/taxonomy, approve evidence automatically, increase Thesis
confidence, or generate trading execution before implementation; each requires an
explicit human governance decision.
