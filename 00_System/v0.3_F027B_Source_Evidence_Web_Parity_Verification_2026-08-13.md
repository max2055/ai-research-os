# F-027B Source and Evidence Web Parity Verification

Date: 2026-08-13
Status: feature and loopback smoke PASS; repository Gate pending final integration commit
Branch candidate: `codex/web-only-parity`

## Scope and authority

This package closes Source capture/maintenance, structured Event and Report creation,
and generic human Review Decision website parity. It does not close F-027C research
workflows, operations/scheduler/recovery parity, CLI retirement, or any F-023
time-dependent or named-human release Gate.

All generated Source, Event, and Report objects begin `review_status: pending`.
Processing a Source or creating an Event does not approve the Source. Only the fixed
local human Web identity can prepare and commit a Review Decision. Automation receives
no browser session, CSRF value, preview token, or approval capability, and no route in
this package changes a Thesis conclusion or confidence.

## Delivered contract

- A shared repository mutation coordinator freezes complete create/replace write sets,
  before/after hashes, target version, and bounded summaries under the signed preview.
- Commit accepts only session-bound CSRF and a signed one-use preview token. It never
  accepts actor, final path, generated Markdown, captured bytes, or reviewed content.
- SQLite audit failure after filesystem publication restores frozen originals and
  removes creates; a redacted path/hash recovery manifest records compensation.
- Source URL and bounded browser-file capture run once during preview. New version
  fetch, latest-asset extraction, date confirmation, and read-only asset verification
  are available from the Source workbench.
- Event creation uses the existing strict Pydantic spec, processed-Source quote anchors,
  fact/inference/judgment separation, alternative explanations, unknowns, and Thesis
  relationship proposals. It also retains the existing Source extraction checklist
  update in the same transaction.
- Report synthesis accepts only reviewed Evidence and retains contradicting Evidence,
  source-independence groups, unknowns, and investment-boundary language.
- Review approve/edit/reject calls the existing domain guard, freezes the Review
  Decision and every target/superseded Report replacement in one transaction, and binds
  reviewer to the fixed human Web identity.
- The product capability registry covers all exact Source, Event, Report, and Review
  preview/commit routes; Dashboard security tests retain an exact non-GET allowlist.
