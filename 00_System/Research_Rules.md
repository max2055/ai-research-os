# 研究行为规则 v0.1

## 1. 陈述类型

每个重要陈述必须属于以下一种。

### Fact

来源直接支持、可以被外部核验的陈述。

要求：

- 引用 Source ID。
- 保留时间、范围、口径和单位。
- 不超出来源原意。
- 公司自述标记为“公司披露”或“公司声称”。

### Inference

由一个或多个事实推导出的解释。

要求：

- 明确写出推理步骤。
- 说明依赖的事实。
- 提供至少一个替代解释。
- 不伪装成来源直接结论。

### Judgment

研究者对产业、公司或投资含义的判断。

要求：

- 关联 Thesis。
- 标注置信度。
- 列出支持和反面证据。
- 给出可证伪条件与复盘时间。

## 2. 引用规则

1. 所有关键事实必须可回溯到 Source。
2. 优先引用原始来源。
3. 二手来源引用原始数据时，尽可能找到原始出处。
4. 同一事实被多家媒体转载不构成多项独立证据。
5. 来源无法访问或无法核验时，降低来源等级并明确说明。
6. 引用必须支持紧邻的陈述，不能只在文末堆积链接。
7. 不得引用 AI 生成文本作为事实来源。

### 2.1 Source、Processing 与 Event 审核

- Source processing 表示捕获、注册、提取或链接等动作是否完成，不代表内容获得人工批准。
- Source `review_status: reviewed` 表示完整 Source 记录的身份、出处、等级、摘要、限制和可访问位置已由人工核验。
- Event `review_status: reviewed` 表示该 Event 使用的具体来源片段、Fact、Inference、Judgment 和关系已经人工核验。
- reviewed Event 可以临时引用 pending Source；这只表示 Source 级完整审核仍有治理积压，不会自动降低或提升 Source 状态。
- 从 Source 创建 Event 时必须同步记录 extraction 已完成，但不得自动把 Source 标为 reviewed。
- final Report 若依赖底层仍为 pending 的 Source，必须披露该 Source 级审核缺口。

## 3. 时间规则

- 区分事件发生日、信息发布日期和研究访问日。
- 使用最新状态回答当前问题时，必须核验资料时效。
- 财务指标必须保留报告期。
- 产品能力必须说明版本和发布日期。
- 快速变化的判断需要设置复盘日期。

## 4. 反证规则

每项 Thesis 都必须主动寻找：

- 直接反面证据。
- 不同作用机制。
- 与结论一致但原因不同的替代解释。
- 时间过早或时间过晚的可能性。
- 产业方向正确但公司无法获取价值的可能性。
- 公司受益但估值已充分反映的可能性。

没有发现反证不等于不存在反证。

## 5. 置信度规则

置信度表示当前证据条件下判断成立的主观概率，不表示事实精度。

| 区间 | 含义 |
|---:|---|
| 0.00～0.19 | 仅有想法，缺少有效证据 |
| 0.20～0.39 | 有初步线索，存在重大未知 |
| 0.40～0.59 | 正反证据接近，暂不形成强判断 |
| 0.60～0.79 | 多项较强证据支持，仍有明确反证风险 |
| 0.80～0.94 | 多源高质量证据和实际结果持续支持 |
| 0.95～1.00 | 原则上不用于产业预测 |

置信度更新必须记录：

- 更新前数值。
- 更新后数值。
- 新增 Evidence ID。
- 为什么该证据具有区分度。
- 是否出现相关但不独立的重复证据。

禁止仅因新闻数量增加而提高置信度。

## 6. 技术与投资的隔离规则

以下推理均不成立，除非补足中间机制：

- 技术领先，所以公司值得投资。
- 产品发布，所以会产生收入。
- 客户试点，所以会规模化部署。
- 用户增长，所以会形成利润。
- 市场增长，所以所有参与者都会受益。
- 公司受益，所以股票一定上涨。

必须继续回答：

- 谁付费？
- 付多少钱？
- 是否新增预算？
- 成本和毛利如何？
- 谁拥有定价权？
- 竞争会否转移价值？
- 当前估值反映了什么预期？

## 7. Agent 工作规则

Agent 可以：

- 注册 Source 草稿。
- 提取 Fact 和 Event 草稿。
- 提议实体与 Taxonomy 标签。
- 提议 Thesis 关联。
- 生成索引和报告草稿。
- 检查缺失字段、引用和逻辑跳跃。

Agent 不可以：

- 自动批准 Evidence。
- 自动修改 Thesis 结论或置信度。
- 删除反面证据。
- 修改原始材料。
- 在来源不足时补写“合理事实”。
- 生成自动买卖指令。

所有 Agent 产物默认：

```yaml
review_status: pending
```

## 8. 冲突处理

当来源冲突时：

1. 保留全部来源。
2. 检查时间、定义、样本和统计口径。
3. 比较来源独立性和等级。
4. 不强行合并不兼容的数据。
5. 在 Event 或报告中标记冲突。
6. 将解决冲突所需资料加入研究队列。

## 9. 输出前检查

- [ ] 关键事实均有 Source ID。
- [ ] 公司披露与独立验证已经区分。
- [ ] Fact、Inference、Judgment 已经分离。
- [ ] 推理链没有跳过商业机制。
- [ ] 包含反面证据和替代解释。
- [ ] 包含未知事项。
- [ ] 置信度符合证据质量。
- [ ] 包含证伪条件。
- [ ] 包含后续观察指标和复盘日期。
- [ ] 没有自动生成买卖建议。
