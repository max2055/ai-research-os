## Scope

Operations, jobs and scheduler inspection, channel administration, health, metrics,
backup, recovery, discovery, export and release-readiness surfaces are available in
the website. Cadence review is available at `/reviews/cadence` with Weekly/Monthly
preview and signed commit. `python -m research_os.ui` is the local launch mechanism. Existing CLI
services are internal compatibility/recovery code, not a second product interface.

## Mutation contract

Operational writes use preview, signed one-use token, CSRF, fixed human actor,
stale/version check, audit and atomic commit/compensation. Job preview freezes an
operational request with `authority: operational_human`; commit publishes that request
through the shared repository mutation coordinator and then runs the server-side Job
service, producing a Job result and audit trail. Channel enablement validates review and
license policy before preview. Backup, recovery, export and release readiness remain
explicit, bounded and auditable; release readiness is read-only.

Automation may execute an explicitly prepared operational job, but cannot approve
Source/Event/Report/Review objects or modify Thesis conclusion/confidence. Job output
does not write `03_Theses`.

## Superseding note — 2026-08-18

The 2026-08-13 PASS remains a historical statement about route parity at commit
`223fc59ac8f1d44dccaefdc9134e861a2694d2bc`; it did not prove full scheduler management.
At that point operational Job requests still used repository mutation coordination and
the website did not own schedule create/edit/pause/resume, worker supervision, leases,
heartbeat, missed-run policy, or database-backed run history.

The current implementation supersedes that runtime architecture:

- `python -m research_os.ui` supervises one child Worker for the website lifespan;
- `/operations/schedules` provides typed preview/one-use-confirm flows for schedule
  creation, editing, pause, resume and run-now;
- `09_Automation/operational/operations.db` is authoritative for schedules, leases,
  heartbeat, runs and operational audit; historical Job Markdown remains unchanged;
- durable backup includes a verified SQLite snapshot and manifest for `operations.db`;
- website shutdown terminates the Worker and stops scheduled execution; restart applies
  `catch_up_once` at most once or advances `skip_missed` without execution.

Implementation evidence is defined by
`docs/superpowers/plans/2026-08-17-web-hosted-worker-scheduler.md` and exercised by
`test_operations_db.py`, `test_schedule_control.py`, `test_schedule_migration.py`,
`test_scheduler_worker.py`, `test_worker_supervisor.py`, `test_web_scheduler.py`,
`test_web_worker_lifecycle.py`, `test_durable_backup.py` and
`test_web_operations_parity.py`. This engineering cutover does not alter the original
release decision or any Thesis conclusion/confidence.
