Nearest-rank p95 uses rank `ceil(0.95 * 7) = 7`, so the seventh ranked sample,

`queue_rows` path and `render_candidate_list`.

### Deterministic fixture distribution

- Status: 8,000 `new`; 2,000 `dismissed` (`index modulo 5 == 0`).
- Channel: four channels with 2,500 rows each (`index modulo 4`).
- Entity proposal: 5,000 `COM-aliyun`; 5,000 `COM-benchmark-other` (even/odd index).
- Priority: 9,000 non-NULL; 1,000 NULL. Non-NULL score is
  `(index * 37 modulo 1000) / 1000`.
- Duplicate clusters: 2,500 members in 1,250 deterministic pairs
  (`index modulo 8 in {0,4}`).
- Candidate IDs are zero-padded ascending indexes; discovery timestamps and all
  locators are deterministic. No live Candidate row is copied into the fixture.

### Engineering judgment

The p95 is below 2.0 seconds, so the conditional optimization gate is closed. The
recorded plan does use a temporary B-tree for ordering and scans cluster members,
but measured latency does not justify a schema migration. No Candidate index,
schema, migration, or rollback changed between baseline `982c55d` and `6bf5ca7`.
Per the approved gate, no second run or cProfile session was required.

## Profile and correction

Before correction, the same benchmark measured Home p95 7.675100s and Company p95 2.906065s. cProfile showed:

- Home called `validate_repository` 8 times and loaded 8272 Markdown documents.
- Company called `validate_repository` 3 times and loaded 3102 Markdown documents.
- YAML parsing dominated cumulative time; Candidate SQL and path expansion were not the bottleneck.

The correction added pure `*_from_objects` query helpers. `industry_home_snapshot` and `company_snapshot` now validate once and pass the same immutable object list to Daily Brief, Channel due, Forecast status, Action, metrics, and coverage calculations. This is request-scoped preloading, not stale authority and not a cross-request cache.

## Limits

These are local single-user measurements on the current machine. The 10,000-row
Candidate Queue path is measured, but multi-user concurrency, distributed operation,
and 100,000-row Candidate scale are not. PostgreSQL, a graph database, a vector
store, and a persistent cross-request cache remain untriggered.
