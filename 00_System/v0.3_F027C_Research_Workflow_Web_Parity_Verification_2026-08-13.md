## Scope and authority

The website is the sole product interface for Project, Entity, Ontology, Company,
Impact, Analysis, Thesis Proposal, Forecast, Valuation, Scenario, Recommendation,
Action, Candidate, Source, Event, Report and Review workflows. CLI modules remain
internal compatibility, diagnostic and recovery code only; no product CLI entry point
is required.

Preview validates inputs and runs any provider/capture operation once, freezes a bounded
write plan, target version and hashes, and issues a signed one-use token. Commit accepts
only that token and CSRF, rechecks version, publishes atomically, records audit and
compensates on publication/audit failure. Browser input cannot replace actor, paths,
generated Markdown or captured bytes.

Generated research objects default to `review_status: pending`. Only the fixed local Web
human identity can apply a Review Decision. Automation has no browser session, CSRF or
approval capability and cannot approve a research object or change Thesis conclusion or
confidence. Thesis proposals write only to `05_Research/Analysis_Proposals`.

## Verification

The final non-local suite passed 836 tests, with one skip and 38 local-integration tests
deselected. Focused Web suites cover registry, Candidate, Source/Event/Report/Review,
Impact/Analysis and Decision preview/commit/replay, hostile Origin, CSRF, stale target,
fixed actor, capture-once semantics, compensation and unchanged Thesis digests.

Disposable loopback HTTP smoke verified representative Project, Impact, Decision and
research-object mutations with preview `200`, commit `303`, result `200`, replay `409`,
hostile Origin `403`, and automation actor rejection. No smoke artifact touched the
authoritative workspace.

F-027C Web parity is PASS. This engineering record does not approve a Thesis or v0.3.
